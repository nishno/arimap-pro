## მიზანი

## ამ ვერსიის გამოყენება

`npm run build`, შემდეგ `npm run local:start`. არსებული მფლობელით შესვლის შემდეგ Core-ის ზედა ზოლში აირჩიეთ **Weigh terminal · Pilot** / **აწონვის ტერმინალი · საპილოტე**. შესაძლებელია `/terminal/index.html`-ის პირდაპირ გახსნაც.

საჭიროა უკვე არსებული ფერმის `harvestEvents` ღონისძიება და `employees` აქტიური თანამშრომელი. სატესტო მონაცემები ავტომატურად არ იქმნება. Cloud რეჟიმში ტერმინალი ჯერ არ მუშაობს.

ეს არის ცალკე საპილოტე რეესტრი: არ ცვლის ხელფასებს, მარაგებს ან მოქმედი კრეფის ჯამებს. შემოწმების ღილაკიც მხოლოდ საპილოტე სტატუსს ცვლის. მუშის ბარათების, განმეორებითი ყუთის გამოყენების და ბიზნესმიღების საბოლოო წესები შემდეგ ეტაპზე უნდა დაემატოს.

## შესრულების შემდეგი რიგი

1. ამწონველის event-scoped სერვერული უფლება და API იზოლაციის გაფართოება.
2. უსაფრთხო ოფლაინ სამუშაო პაკეტი/განბლოკვა, პარალელური ჩანართების კოორდინაცია და ავტომატური retry/backoff.
3. მიღების ციკლის ID, საეჭვო ჩანაწერის გადაწყვეტის სრული პროცესი და ავტორიტეტული projection.
4. მოწყობილობის ადაპტერები და რეალურ აღჭურვილობაზე ტესტი.
5. მცირე საველე პილოტი და შეჯერება.
6. სხვა hardware აპები; მხოლოდ ამის შემდეგ ძველი მძიმე იმპორტების მოცილება.

დროისა და პროცესორის გამოყენების დაპირებები გაზომვის გარეშე არ კეთდება.
